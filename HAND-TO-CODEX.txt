【工作流程】

1. 改代码
2. 提交并推送：
     git add -A && git commit -m "说明你改了什么"
     git push origin main
   推送经常因网络失败，重试即可：
     H=$(git rev-parse --short HEAD)
     for i in $(seq 1 15); do
       git push origin main >/dev/null 2>&1
       R=$(git ls-remote origin main 2>/dev/null | cut -c1-7)
       [ "$R" = "$H" ] && { echo "pushed $H"; break; }
       sleep 12
     done
3. 等 3-5 分钟，然后运行：
     ./check-ci.sh
   这个脚本会用仓库里已配置好的凭据读取 CI 日志，自动判断通过还是失败。
   不要自己拼 gh 命令，不要去找 token，直接用这个脚本。

4. 如果失败，脚本会列出具体报错。修掉再推一次。

一次 CI 大约 5-11 分钟。

【什么算通过】

./check-ci.sh 最后一行必须是 ">>> 通过"，并且上面列出：
    PASS: 65 model checks
    PASS: tutor chain checks
    PASS: tutor log checks
    ** BUILD SUCCEEDED **      （要出现两次：真机 + 模拟器）
    PASS: plist 关键项齐全

少任何一条都不算通过。特殊情况：
- ">>> 被取消" 不是失败，是 CI 队列被打断，重推或重跑即可。
- 脚本说"还没跑完"就等几分钟再跑。

【干活规矩】

- 一次只做一件事。做完告诉我：改了什么、CI 结果、还有什么不确定。不要一口气改五个文件然后说"应该没问题"。
- 绝对不许简化宽容解码（HANDOFF 第 5 节）。那些看着多余的 decodeIfPresent 是修过真实数据丢失事故的。
- 绝对不许删除与用户数据保存相关的逻辑。看不懂就问。
- 改模型字段时，必须同时手写 init(from:) 加默认值，并补一条"缺字段也能解码"的测试。
- android/ 目录已废弃，不要参考、不要改。
- 仓库里有调试截图和旧脚本（*.png、fix-*.bat 等），都是垃圾，不要清理。要清理先问我。
- 我不懂 Swift。所有报错和方案用中文说清楚：哪里坏了、什么后果、你打算怎么修、修完我怎么验证。
